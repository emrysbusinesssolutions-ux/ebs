Commitments

Six commitments you can hold us to

Security claims are easy to write. These are the controls and operating habits behind the system, stated without a certification badge we do not hold.

Data ownership

The database lives on your computer. You own the data, the hardware it runs on and the backups made from it. There is no EBS cloud holding your records.

Least-privilege roles

Roles are set per module and action. Staff see the areas their role allows, and branch permission gates apply where the business runs more than one branch.

Audit trail

An audit log records changes, so you can review who changed stock, prices or permissions, and when. Login sessions are part of the record.

Daily backups

An automated backup runs every day. Retention is 30 days on Basic, 90 days on Standard and 1 year on Premium.

Monitoring

A watchdog checks the server every five minutes and restarts it if it stops responding. Events are recorded.

No lock-in

Excel and CSV export are built in, and the database is yours. If you ever leave, you take the data with you.

Architecture

A shop server, not a cloud account.

EBS is deployed remotely onto a computer you control. The application, database and backups sit on your premises; devices connect over your local network. The system keeps working when the internet does not.

  • The server runs on a computer in your shop or office
  • Phones, tablets and laptops connect over the shop LAN
  • The web app is offline-first, with a local database on the device
  • Changes sync with the server when a connection returns
Access and audit

The application and database run on a computer in your shop or office. Automated backups are part of the same system.

Access control & audit

Who can do what, and who changed it

Access is granted by role, not shared as one administrator login. The audit log gives you a reviewable record of changes across stock, prices and permissions. Remote support runs on request over a supervised session — no standing access and no unattended connections.

Least-privilege roles

Permissions are defined across a role × module × action matrix, so a counter role and an owner role do not carry the same reach.

  • Staff see only the modules their role allows
  • Per-branch permission gates for multi-branch teams
  • Login sessions are recorded
  • Credentials are handled with encryption, not plain text

An audit trail you can review

The audit log supports stock, price and permission reviews. It answers the questions that matter in a dispute: who changed this, and when.

  • Records changes with the user and time
  • Covers stock, price and permission changes
  • Login sessions form part of the record
  • Available in the system you already run

Why roles matter: the biggest data risk in a shop is usually a shared login. Role-based access means a mistake or a departure can be traced and contained without changing everyone else's credentials.

Backup & continuity

Backups are tested, not assumed

A backup is only useful if it restores. Daily backups run automatically, and restore drills are part of the operating routine.

Daily automated backups

A backup runs automatically every day. Retention is 30 days on Basic, 90 days on Standard and 1 year on Premium.

Weekly verification and drills

Backups are verified weekly, and restore drills are run so recovery is exercised rather than assumed.

A clear recovery point

If hardware fails, the latest verified backup is the recovery point. We help with the restore; the hardware itself is part of your environment.

Honest boundary: on-premise means your computer is the server. Power, physical access and hardware replacement belong to your environment. The software, the backup routine and restore help belong to us.

Monitoring

Designed for 24/7 operation

Monitoring and auto-restart reduce the time a stopped server stays stopped. They are not an uptime guarantee, and we do not publish an uptime percentage.

Health checks every 5 minutes

A watchdog checks the server and application on a five-minute cycle, all day.

Watchdog auto-restart

If the process stops responding, the watchdog restarts it and records the event for review.

Built for continuous use

The system is designed to run through the working day and beyond. Availability also depends on power, hardware and your network.
